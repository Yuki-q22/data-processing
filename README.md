# 数据处理工具平台

面向招生数据清洗、标准化、匹配、校验和导出的浏览器端工具集。项目采用 React + TypeScript 构建，大部分 Excel、PDF 和图片处理在浏览器本地完成；规则中心通过 Firebase Authentication 和 Realtime Database 提供登录、管理员权限与规则同步。

README 会被应用内“使用规则 / README”弹窗直接加载。修改工具名称或章节标题时，请同步检查 `src/config/toolRegistry.tsx` 中的 README 导航关键词。

## 项目特点

- 单页应用，工具页面按需加载，避免一次性加载全部处理模块。
- Excel 解析运行在共享 Web Worker 中，减少大文件处理对页面交互的阻塞。
- 使用 Zustand 管理任务、预览、规则和人工匹配状态。
- 处理结果绑定输入版本；修改年份、文件、Sheet 或基础信息后，旧结果不能继续导出。
- Excel 导出使用统一列宽和对齐规则，并按稀疏单元格遍历，避免空白区域造成内存膨胀。
- 文件上传同时校验扩展名、文件大小和 XLSX/XLS/PDF 文件头。
- 页面级异步任务带有竞态保护，重置或重新上传后不会回写过期结果。
- 应用入口带全局错误边界；部署头文件包含 CSP、防嵌入和基础安全响应头。
- 同时提供浏览器端工具和独立 Python 备注检查脚本。

## 1. 规则中心

规则中心为其他工具提供共享规则。未配置 Firebase 时，页面仍可加载内置默认规则，但登录、云端同步和管理员写入不可用。

支持的规则类型：

- 学校名称规则。
- 学校、专业、层次组合规则。
- 备注招生类型关键词、输出类型和优先级。
- 备注“需要核查”排除关键词。
- 按年份、省份维护的招生科类和现行批次规则。
- 按年份、省份维护的省控线科类和省控线批次规则。

规则导入字段：

| 规则类型 | Excel 必需字段 |
|---|---|
| 学校名称 | `学校名称` |
| 专业名称 | `招生专业`，可结合层次形成组合规则 |
| 备注招生类型 | `备注查找字段`、`输出招生类型`，可选 `优先级` |
| 省份科类批次 | `年份`、`省份`、`招生科类/科类`、`招生批次/批次` |
| 省控线科类批次 | `年份`、`省份`、`省控线科类`、`省控线批次` |

登录方式支持邮箱密码和 Google 登录。规则读取要求已登录；写入要求：

```text
admins/{uid} = true
```

新增、更新、删除、导入和排序操作会把规则数据及 `rule_center/meta` 版本信息放在同一次 Firebase 原子更新中。

## 2. 专业分模板智能填充

处理流程分为六步：

1. 上传原始专业分和招生计划，设置年份、数据来源、学校或省份兜底值。
2. 自动生成字段映射，按需调整目标字段或忽略源字段。
3. 查看标准化、科类、批次和现行批次规则。
4. 预览处理结果、匹配状态、警告和错误。
5. 处理未匹配、多候选和其他异常记录；多候选记录可人工指定计划。
6. 仅在处理结果仍对应当前输入时导出专业分模板。

原始专业分允许随机表头，不强制固定字段名；需要在字段映射步骤指定目标字段。招生计划上传会检查以下字段：

```text
年份、省份、学校、科类、批次、招生类型、专业、层次、方向、备注、
招生人数、招生代码、专业代码、专业组代码、专业组选科要求、
专业选科要求(新高考专业省份)、数据来源
```

核心匹配策略：

- 先按学校、省份、专业建立索引，再按科类、批次、层次和招生类型逐级匹配。
- 精确匹配失败时，可尝试忽略批次或清理空格、中文/英文括号后匹配。
- 学校 + 省份 + 科类 + 专业组合重复时不自动强行消歧，交给异常页人工确认。
- 人工指定的招生计划优先级最高。
- 原始批次不在对应年份、省份现行批次规则中时，可使用匹配计划批次。
- 招生计划选科字段会转换为首选科目、选科要求和次选科目。
- 指定年份没有省控线规则时返回空结果，不回退到其他年份。

## 专业提取工具

用于从“大类招生表”的专业备注中提取“标准专业表”内的专业名称。

输入：

- 大类招生表：仅支持 `.xlsx`；第 5 列为层次，第 7 列为备注。
- 标准专业表：仅支持 `.xlsx`；第 1 列为层次，第 2 列为标准专业。

处理结果写入大类招生表第 8 列 `提取标准专业`。匹配会优先处理长专业名，排除括号方向内容和“外语要求：英语”等非专业语境，单行结果自动去重。输出文件名为：

```text
原文件名_提取后.xlsx
```

## 3. 院校分提取

页面包含“普通类”和“艺体类”两个标签页，共享规则中心的学校、专业和省控线规则，但处理逻辑分别维护。

### 普通类

- 支持专业分原始模板和专业分库中导出模板。
- 按学校、省份、科类、批次、招生类型、专业组代码和招生代码等字段分组。
- 分组内最低分取最低值、最高分取最高值，人数类字段求和。
- 代码字段按文本导出并去除开头的 `^`。
- 省控线科类和批次按上传数据年份匹配；提前批等特殊招生批次不填写普通省控线。

### 艺体类

- 按学校、省份、招生类别、招生批次、专业类别、招生代码、专业组、备注和是否校考等字段分组。
- 输出投档分、位次、专业组和校考信息。
- 学校与专业名称继续使用规则中心校验。

## 4. 模版转换工具

页面包含三个标签页。

### 学业桥专业分转换

- 将学业桥专业分转换为专业分导入模板。
- 标准化学校、省份、科类、批次、层次和代码字段。
- 解析报考要求，生成首选科目、选科要求和次选科目。
- 清洗专业备注并输出问题列表、修改后备注和数据问题标记。

### 学业桥计划转换

- 将学业桥计划数据转换为招生计划目标模板。
- 输出学校、专业、层次、科类、批次、招生类型、代码、人数、学制、学费和选科字段。
- 使用规则中心校验学校与专业组合，并保留原始报考要求和批次备注供核对。

### 专业分导出模板转换

- 将库中导出的专业分模板转换为专业分导入模板。
- 源文件年份写入目标模板固定位置，目标数据从第 4 行开始。
- `学校/专业/备注/方向` 分别转换为目标模板对应字段。
- 物理类和历史类推导首选科目；新疆、西藏按既有老高考规则处理。
- 专业组代码、招生代码和专业代码去除 `^` 并按文本格式导出。

## 5. 专业组代码匹配

输入专业分导入模板和招生计划模板，根据年份、学校、省份、专业、科类等信息补充专业组代码和选科要求。

| 状态 | 含义 |
|---|---|
| 原有代码 | 专业分中已经存在代码 |
| 自动匹配 | 找到唯一可靠候选并自动补充 |
| 待手动补充 | 候选重复、缺失或存在异常 |
| 已手动补充 | 用户已在页面中指定或填写 |
| 未匹配到候选 | 招生计划没有对应记录 |

页面支持省份筛选、只看待处理记录、候选计划选择和代码/选科字段手工补充。

## 6. 图片下载

输入就业质量报告等公开网页链接，读取 HTML 中的静态 `<img src="...">`，预览后合成为 PDF。

处理限制：

- 网页响应体最大 10 MB。
- 单页最多处理 200 个图片地址。
- 单张图片最大 20 MB，已读取图片总量最大 200 MB。
- 图片并发请求数为 6，单个网页或图片请求超时为 20 秒。
- 非图片响应会被拒绝。
- 浏览器跨域策略仍可能阻止网页或图片读取。

PDF 文件名来自网页标题，并自动替换操作系统不允许的文件名字符。

## 7. 招生计划数据比对

检查招生计划记录是否已经存在于专业分或院校分文件中。

- 招生计划文件必传，专业分和院校分文件可选。
- 分别生成“招生计划 vs 专业分”和“招生计划 vs 院校分”的匹配结果。
- 支持省份、匹配状态和招生代码缺失状态筛选。
- 可分别导出专业分缺失模板和院校分缺失模板。
- 科类、批次和省控线处理使用对应年份的规则中心数据。

## 8. 备注处理

页面包含两个标签页。

### 备注招生类型提取

- 自动识别常见备注字段，也允许手动选择。
- 按规则中心关键词和优先级提取招生类型。
- 命中排除关键词时标记“需要核查”，并避免在否定语境中错误提取。
- 导出备注、招生类型、是否需要核查及命中关键词。

### 备注处理

- 检查 OCR 常见错字、异常字符、单位和值域问题。
- 统一中英文括号和标点，清理多余空格、空括号和嵌套括号。
- 标注重复括号内容、分隔重复内容和连续重复短语。
- 低置信度问题只提示人工核查，不强制改写。
- 保留原字段并新增 `备注问题标注` 和 `修改后备注`。

项目根目录还提供同规则体系的 Python 独立脚本，使用方式见“独立 Python 备注检查”。

## 9. 高考真题题目截图

将文档版高考真题 PDF 按顶层题号裁剪成 PNG，并打包为 ZIP。

- 识别 `1.`、`1．`、`1、` 等顶层题号，不把 `（1）` 等小题号当成新题。
- 识别选择题、非选择题等大标题，并把它作为上一题结束边界。
- 跨页题目会拼接多个页面片段。
- 支持清晰度、白边、跨页间隔、边界收缩和页眉页脚忽略范围配置。
- ZIP 附带 `_detected_questions.txt`，用于核对识别结果。

适合带文本层的 PDF；纯扫描 PDF 通常无法自动识别题号。

## 10. 一分一段处理

- 校验工作簿固定位置的年份信息。
- 检查分数连续性并自动插入缺失断点，新增行使用黄色标记。
- 根据省份补充分数上限后缀：上海 `-660`、海南 `-900`、其他省份 `-750`。
- 自动补充人数、累计人数校验和分数校验结果。
- 吉林、贵州等特殊格式使用模块内置解析规则。
- 支持 `.xlsx`、`.xls`、`.csv`、文本型 PDF，以及直接粘贴表格/OCR 文本。

## 本地运行

### 环境要求

- Node.js `^20.19.0` 或 `>=22.12.0`。
- npm。
- 运行独立 Python 脚本时需要 Python 3.10+ 和 `openpyxl`。

### 安装与启动

```bash
npm install
```

复制环境变量文件：

```powershell
Copy-Item .env.example .env.local
```

请在 `.env.local` 中填写或替换目标 Firebase 项目的配置：

```env
VITE_FIREBASE_API_KEY="..."
VITE_FIREBASE_AUTH_DOMAIN="..."
VITE_FIREBASE_DATABASE_URL="..."
VITE_FIREBASE_PROJECT_ID="..."
VITE_FIREBASE_APP_ID="..."
```

启动开发服务器：

```bash
npm run dev
```

默认访问地址通常为 `http://localhost:5173`。

### 构建和预览

```bash
npm run build
npm run preview
```

生产构建输出到 `dist/`。

## Firebase 配置

主要数据结构：

```text
admins/
  {uid}: true

rule_center/
  school_name/
  major_combo/
  remark_enrollment_type/
  exclusion_keywords/
  province_category_batch/
  control_line/
  meta/
    version
    updatedAt
```

仓库中的 `database.rules.json` 执行以下权限策略：

- 根节点默认禁止读写。
- `rule_center`：已登录用户可读，仅管理员可写。
- `admins/{uid}`：用户只能读取自己的管理员标记，客户端不能写管理员列表。

部署数据库规则前，请先确认 Firebase CLI 当前项目：

```bash
firebase use
firebase deploy --only database
```

生产环境不要只依赖页面上的管理员判断；真正的写入权限由 Realtime Database 安全规则控制。

## 部署说明

这是静态前端项目，可部署到 Cloudflare Pages、Netlify、Vercel 或其他支持 SPA 的静态托管平台。

推荐配置：

| 配置项 | 值 |
|---|---|
| Framework | Vite |
| Build command | `npm run build` |
| Output directory | `dist` |
| Root directory | 项目根目录 |

部署平台需要配置与 `.env.local` 对应的五个 `VITE_FIREBASE_*` 环境变量。

`public/_headers` 提供 CSP、HSTS、`X-Frame-Options`、内容类型保护和缓存策略。托管平台必须支持该文件格式；不支持时需要在平台配置中设置等价响应头。`public/_redirects` 用于 SPA 路由回退。

如果页面可打开但规则无法读取或写入，依次检查：

1. Firebase 环境变量是否完整。
2. Authentication 是否启用了对应登录方式。
3. Realtime Database 规则是否已经部署。
4. 当前用户 UID 是否存在于 `admins/{uid}`。
5. 浏览器控制台和规则中心是否显示权限或网络错误。

## 文件与性能限制

通用上传默认最大 100 MB。Excel Worker 额外限制：

| 项目 | 限制 |
|---|---:|
| 工作簿 Sheet 数 | 50 |
| 单 Sheet 行数 | 300,000 |
| 单 Sheet 列数 | 512 |
| 工作簿估算单元格数 | 5,000,000 |
| Worker 工作簿缓存 | 3 份，按最近使用保留 |
| Worker 单请求超时 | 120 秒 |

超过限制会直接给出错误，不会继续解析。替换或重置工作簿时会释放 Worker 缓存；浏览器回收工作簿对象时也会尝试通知 Worker 释放对应资源。

## 独立 Python 备注检查

`check_remarks.py` 可在不启动前端的情况下处理 `.xlsx`：

```bash
pip install openpyxl
python check_remarks.py input.xlsx
```

如果省略路径，脚本会提示输入。脚本会：

- 遍历所有包含标准备注列的 Sheet。
- 保留原工作簿结构和已有样式。
- 新增 `备注问题标注` 和 `修改后备注`。
- 对问题单元格使用黄色填充。
- 使用稀疏单元格遍历，避免格式化大块空白区域。
- 如果默认输出文件已存在，自动追加 `_1`、`_2`，不覆盖已有结果。

## 数据处理注意事项

1. 不同工具的表头行不同，上传前应先核对页面说明和模板固定位置。
2. 专业分智能填充的原始专业分不要求固定表头，应在字段映射页确认对应关系。
3. 年份会影响科类、批次和省控线；修改年份后必须重新处理。
4. 导出前应处理 `matched_multiple`、`unmatched`、warning 和 error 记录。
5. 规则中心被多个工具共享，修改规则后应重新运行相关文件。
6. 代码字段按文本处理，避免 Excel 去掉前导零；已有 `^` 前缀会按各工具规则清理。
7. 大文件解析虽在 Worker 中执行，导出和 PDF 渲染仍可能占用较多浏览器内存。
8. 点击重置会取消当前页面结果写回，但已经开始的浏览器底层计算可能需要短时间结束。
9. 上传和处理均在浏览器内存中完成，刷新页面后需要重新上传文件。

## 已知限制

- 图片下载受目标网站 CORS、鉴权、防盗链和网络状态影响。
- 纯扫描 PDF 没有文本层时，高考题号识别效果有限。
- 项目没有后端任务队列，不适合在单次浏览器会话中处理超出限制的超大数据集。
- Firebase 配置缺失时，云端规则能力不可用。
- 部分 Excel 公式、宏、外部链接或特殊格式在浏览器转换后可能无法完整保留，应使用样本文件验证。
